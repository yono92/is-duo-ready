# AdSense — 자동 광고 전용

업데이트: 2026-11-02. 사용자 결정에 따라 홈 6번째 앱 뒤의 고정 광고 공간을
제거하고 Google 자동 광고만 사용한다. 수동 `ins.adsbygoogle`, `data-ad-slot`,
`adsbygoogle.push`는 추가하지 않는다. 계정에 생성된 수동 광고 단위
`IsDuoReady / 2712791143`은 사이트에서 사용하지 않으며 계정에서 삭제하지 않았다.

## 구현

- 게시자: `ca-pub-8224851078290204`. 기존 인증 메타 태그와 `public/ads.txt`를 유지한다.
- `src/components/auto-ads.tsx`: `next/script`의 `afterInteractive`로 게시자 스크립트를
  한 번 로드한다. 위치·개수·형식은 AdSense 자동 광고 설정이 결정한다.
- 홈의 실제 앱이 있는 결과, 실제 공개 앱 상세, 실제 변경 이력이 있는 업데이트 화면에 연결한다.
  가상 데이터·로컬·Preview·빈 결과·조회 실패에는 새 광고 스크립트를 로드하지 않는다.
- 관리자·제보·지원 안내·404에는 로더를 넣지 않는다.
- `ADSENSE_AUTO_ADS_ENABLED=true`와 실제 Vercel Production/PostgreSQL/HTTPS 운영 origin이
  모두 있어야 동작한다. 기본값은 비활성이다. 검색 색인 설정과는 독립적이다.

이번 코드 변경은 로컬 작업이다. 실제 운영 광고 요청·승인·동의 동작·배포를 완료한
것으로 해석하지 않는다. 개인정보처리방침과 계정 제외 설정이 미완료여서 활성화하지 않았다.

## 브라우저에서 확인한 계정 상태 — 2026-11-02

- 계정 초기 설정: 모든 단계 완료. 사이트: 준비 중 / 광고 게재 가능 여부 검토 중 / 리뷰가 요청됨.
- 자동 광고 및 자동 최적화: 사용. 앵커·사이드 레일·모바일 전면광고: 모두 사용.
- 제외된 페이지: 0개. 이 상태로 운영 활성화하지 않는다.
- 해당 사이트의 유럽 동의 메시지: 게시됨, 동의하지 않음 선택지 사용.
  게시 상태는 실제 사이트에서 동의가 동작함을 보장하지 않는다.
- 운영 페이지: 확인 당시 광고 스크립트·수동 광고 단위·개인정보처리방침 링크 없음.
- `/ads.txt`: 공개 브라우저에서 정확한 게시자 행을 확인했지만 계정은 찾을 수 없음으로 표시했다.
- 메시지의 개인정보처리방침 URL은 브라우저 창 전환으로 끝까지 확인하지 못했다.

## 운영 활성화 전에 남은 작업

1. 실제 데이터·쿠키·광고 운영에 맞는 ko/en 개인정보처리방침을 공개하고 푸터에 연결한다.
   동의 메시지의 개인정보처리방침 URL도 그 공개 주소로 연결한다. 정책 페이지에는
   광고 태그와 동의 메시지 태그를 넣지 않는다.
2. AdSense 자동 광고의 페이지 제외에 ko/en 각각의 `/admin` 전체 하위 경로,
   `/submit`, `/methodology`, 개인정보처리방침 경로를 등록하고 저장 상태를 확인한다.
   자동 광고는 Next.js 클라이언트 탐색 후에도 이미 실행된 스크립트/DOM을 유지할 수 있다.
   컴포넌트를 제거하는 것만으로 광고 중단을 보장하지 않으므로 계정 제외 설정이 필요하다.
3. 실제 공개 페이지 → 관리자·제보·정책·빈 결과·오류로 이동할 때 광고가 남지 않는지
   확인한다. 특히 빈 결과와 오류는 계정 URL 제외만으로 제어할 수 없으므로 클라이언트
   탐색까지 검증하여 필요 시 문서 이동 경계를 보완한 뒤 활성화한다.
4. 위 조건을 충족한 뒤 기존 Production에만 `ADSENSE_AUTO_ADS_ENABLED=true`를 설정하고
   검증한 코드 스냅샷을 배포한다. 이번 작업에서 환경 값 변경·배포는 하지 않는다.
5. 실제 사이트에서 유럽 동의 테스트, 동의 거부·재설정, 모바일·테마·검색·필터·언어 이동,
   스크립트 중복 요청, 광고 미송출 시 화면을 확인한다. 실제 광고를 클릭하지 않는다.
6. 사이트 승인 및 ads.txt 인식 상태를 다시 확인한다. 광고 미리보기와 실제 송출을 구분한다.
