# AdSense 연결 안내

확인일: 2026-10-30. 현재 구현은 홈 목록의 광고 공간 하나와 사용자 제공 계정
`ca-pub-8224851078290204`의 `google-adsense-account` 메타 태그다. 메타 태그는
`src/app/[locale]/layout.tsx`의 Metadata `other`로 ko/en 공통 head에 제공한다.
사용자 요청에 따라 `public/ads.txt`에 같은 게시자 ID의 Google DIRECT 판매자 행을 추가했다.
광고 스크립트, 광고 단위 ID 및 개인정보처리방침은 아직 추가하지 않았다.
인증 메타 태그와 광고 공간은 6edbe29에서 운영 반영했다. 실제 광고 송출·사이트 승인을
완료한 것으로 해석하지 않는다.

## 현재 공간

- `src/app/[locale]/page.tsx`: 현재 페이지에 7개 이상의 앱이 있을 때 6번째 앱 뒤에 표시.
- `src/app/globals.css`: 전체 카드 열 너비, 광고 콘텐츠 최소 높이 250px, 별도 라벨과 여백.
- `src/messages/{ko,en}.json`: 광고 / Advertisement.
- 6개 이하·빈 결과·조회 오류 및 상세·관리자·제보 화면에는 공간이 없다.
- 로컬 fixture에서도 배치를 미리 볼 수 있지만 실제 광고 요청은 전혀 하지 않는다.

## 계정에서 할 일

1. AdSense에 가입하고 계정의 필수 정보를 입력한다. 사이트 메뉴에서 실제 운영 URL을 추가한다.
   비밀번호 없이 접근할 수 있는 공개 사이트여야 한다. localhost는 심사 대상이 아니다.
2. 사이트 연결 화면의 메타 태그, 광고 코드 또는 ads.txt 중 제공되는 확인 방식을 선택한다.
   초기에는 메타 태그로 소유권만 확인하고 광고 송출은 별도로 준비할 수 있다.
3. 확인 코드를 사이트에 반영하고 배포한 뒤 확인 및 검토 요청을 누른다.
   심사는 보통 며칠, 경우에 따라 2–4주가 걸릴 수 있으며 승인 보장은 없다.
4. 광고 → 광고 단위 기준 → 디스플레이 광고에서 `directory-inline` 등 식별 가능한 이름으로
   반응형 광고 단위를 만들고 코드를 복사한다. 이 사이트에는 수동 광고 단위 하나부터 권장한다.
   자동 광고는 처음에는 끄고 원치 않는 위치·앵커·전면 광고가 생기지 않도록 설정을 확인한다.
5. 사이트 상태가 Ready인지 확인한다. 개인정보처리방침에 광고 관련 데이터·쿠키 사용을
   고지하고, 대상 방문 지역에 맞는 동의를 준비한다. EEA·영국·스위스 개인 맞춤 광고에는
   Google 인증 CMP가 필요하며 AdSense 개인정보 보호 및 메시지에서 Google CMP를 설정할 수 있다.

## 다음 코드 연결에 필요한 값

- 게시자 ID: 사용자 제공 `ca-pub-8224851078290204` (인증 메타 태그에 반영 완료).
- 디스플레이 광고 코드의 `data-ad-slot` 값.
- ads.txt: `google.com, pub-8224851078290204, DIRECT, f08c47fec0942fa0`.

비밀번호·결제 정보·비밀 API 키는 코드 작업에 필요하지 않다. 발급 전에는 임의 ID나
예시 ads.txt를 제품에 넣지 않는다. 프로젝트에는 아직 광고용 환경 변수 계약이 없다.

## 다음 구현 범위

검증 메타 태그는 운영 페이지 head에 반영했다. 사용자는 사이트 심사를 요청한 상태다.
게시자 ID에 맞춘 ads.txt 행은 `public/ads.txt`에 두고 `/ads.txt`에서 제공한다.
현재 proxy matcher는 이 경로를 언어 경로로
리다이렉트하지 않는다. 운영에서 200/text/plain 응답과 올바른 ID를 별도로 확인해야 한다.

승인·동의 설정 후 홈 광고 공간에 실제 광고 단위를 연결한다. 스크립트는 중복 로드를 피하고
Next.js 클라이언트 탐색·검색·필터 변경에서 같은 요소를 중복 초기화하지 않도록 한다.
실제 광고는 운영 데이터에만 허용하고 fixture·관리자·오류 화면은 제외한다. 반응형 광고의
실제 높이가 예약한 250px를 넘을 수 있으므로 Google이 지원하는 크기 설정과 공간을 함께
검증한다. 광고를 CSS로 잘라내지 않는다. 미송출 시 표시 방식도 실제 상태에 맞게 처리한다.
모바일·테마·레이아웃 이동·동의 전후 요청을 확인한 다음 배포한다.
