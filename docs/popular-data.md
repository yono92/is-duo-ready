# 인기 차트 앱 데이터 운영

사용자 요청(2026-10-30): 인기순 UI를 만들기 전에, 사람들이 찾는 앱이 DB에 있고 듀오 지원
상태를 확인할 수 있어야 한다. 첫 대상은 Apple 공식 한국 무료·유료 앱 차트 상위 100개씩이다.

최신 결과: 후속 요청으로 운영 DB를 **1,000개(공개 995개·의료 초안 5개)**까지 확장했다.
아래의 최초 315개 결과는 이전 배치 기록이며, 최신 확장 결과는 마지막 절에 있다.

## 수집과 검토

```sh
node --import tsx scripts/collect-popular-apps.ts --source=docs/data/popular-app-import-2026-10-30.json
```

새 파일이면 공식 피드를 수집한다. 같은 파일을 지정하면 이미 성공한 KR Lookup을 건너뛰고
실패·미완료만 재개한다. 새 날짜의 차트는 새 파일로 수집한다. JSON에는 차트별 순위·국가·
공식 URL·피드 갱신 시각·실제 관측 시각과 KR Lookup 메타데이터가 있다. CSV는 기존 관리자
가져오기에서 사용할 수 있다. 수집 명령은 DB를 쓰거나 지원 여부를 판정하지 않는다.

원본 자료는 기존 `docs/data/` 정책에 따라 Git에서 제외한다. 기록과 운영 DB를 함께 백업한다.
차트 순위는 발견 우선순위이며 실제 사용자 수, 듀오 지원, 배지 존재의 근거가 아니다.

같은 이름의 `.reviews.json` 파일에 **직접 검토한** 명시적 최신 릴리스 노트 근거만 준비한다.
형식은 `{appStoreId, quote, ko, en}` 객체의 배열이다. `quote`는 실제 수집한 공식 릴리스 노트의
정확한 발췌여야 한다. 준비한 근거가 없으면 빈 배열을 사용한다. 이름의 '듀오', 일반 iPad
지원, 폴더블 기기의 일반 언급은 지원 판정이 아니다. 최초 지원 버전·배지·실기기 테스트·사람의
검토 시각을 만들지 않는다. 기존 앱의 새 근거는 별도 정정 절차로 검토한다.

## DB 반영

```sh
node --import tsx scripts/import-popular-apps.ts --target=production --project-ref=YOUR_EXISTING_PROJECT_REF --source=docs/data/popular-app-import-2026-10-30.json
# 출력과 원본 자료 확인 후 같은 명령에 --apply를 붙여 실제 반영한다.
```

기존 0600 hosted 설정과 기존 DB·비공개 아이콘 Storage만 사용한다. 새 프로젝트·배포·
상시 스케줄러는 생성하지 않는다. dry-run은 DB 트랜잭션을 rollback하고 아이콘을 업로드하지
않는다. apply는 기존 콘텐츠를 `.data/release/`에 백업하고 기존 인증 역할·RLS·가져오기·
편집·공개 함수를 사용한다. CLI 실행 UUID의 관리자 allow-list 행은 같은 트랜잭션 안에서
제거하며 상시 관리자를 만들지 않는다.

기존 앱의 공개 상태·근거·검토일·메타데이터를 갱신하지 않고 발견 기록만 추가한다. 신규 앱은
지원 상태, ko/en 설명, 실제 메타데이터, 아이콘을 저장한다. 근거가 없으면 `unknown`이다.
현재 서비스에서 지원하지 않는 공식 장르는 원본 ID/이름을 남기고 분류 null인 초안으로
저장한다. 이를 건강·피트니스 등 다른 분류로 임의 변환하거나 공개하지 않는다.

신규 공개는 기존 `publish_app`으로 이력·공개 스냅샷과 함께 반영한다. 반영 시각은 실제
콘텐츠 처리 시각이며 실기기 테스트일이나 특정 사람이 검토한 날짜가 아니다. 기존 공개
스냅샷 해시가 바뀌거나 차트 앱/지원 상태가 빠지면 트랜잭션을 rollback한다. 아이콘 업로드 후
DB rollback이 발생하면 해시 기반 비공개 파일이 남을 수 있으나 익명 조회 대상이 되지 않는다.

현재 앱 스키마와 게시 정책을 재사용하는 명시적 배치다. 순위는 비공개 발견 기록
`import_proposals`에 보존되며 아직 공개 정렬 기능으로 제공하지 않는다.
