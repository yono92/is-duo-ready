## 반영·재실행·공개 검증

기존 프로젝트에서 비공개 콘텐츠 백업 → dry-run → 원문 검토 → 명시적 apply를 수행했다.
새 앱은 기존 import/save/publish 경로, 지원 정정은 기존 save/publish 경로로 반영했다.
두 언어 요약을 검토한 뒤 current 상태로 재저장했으며 실제 정보 반영 시각과 출처 관측
시각을 구분했다. 검토 이벤트에는 AI 보조 검토임을 남겼고 특정 사람이나 실기기 테스트로
기록하지 않았다. 실행용 임시 관리자 등록은 트랜잭션 안에서 제거했다.

새 앱 9개의 최신 노트 지원을 최초 등록에 반영하고, 기존·신규 앱 99개의 지원과 Outlook
예정 1건을 정정했다. 전체 버전 기록의 마지막 대조에서 지원 6건을 더 확인해 기존 처리
100건은 건너뛰고 추가 6건만 반영했다. 최종 같은 랭킹/지원 배치 재실행에서 신규 앱 0개,
지원 정정 0개, 지원 검토 건너뜀 106개였으며 **콘텐츠 16개 테이블의 해시 변경은 0개**였다.
불필요한 공개 이력·정보 반영일 갱신도 없었다.

최종 정합성 25개 규칙에서 오류 0개. 기존 의료 분류 초안 5개 경고와 최신 릴리스 노트에
없는 과거/공식 컬렉션·발표 근거 41개 경고는 예상된 구분이다. 해당 41개를 근거 소실로
처리하지 않았다. 익명 역할에서 초안 5개의 공개 행·아이콘 조회는 각각 0개였다.

실제 운영 ko/en 홈은 공개 1,181·지원 188·예정 1·미확인 992를 표시한다. 두 언어 홈과
FoxPeek·Goodnotes·Eudic·PlanHalo·Outlook·GenZD·Duo Fold Counter 상세의 총 16개
HTML 확인에서 DB 요약과 일치했다. 신규 FoxPeek 아이콘은 HTTP 200, 22,836 bytes이며
공개 응답 SHA-256이 DB에 저장한 원본 해시와 같았다.

검증: lint(기존 연구 파일 warning 1개), typecheck, 단위 89개, 격리 DB 17개, 공개 Chromium
E2E 32개(2.2m), Webpack 빌드가 통과했다. 기본 Turbopack 빌드는 기존 process/port EPERM으로
실패했다. 병행 중인 다른 제품 수정이 있는 작업 트리에서 실행했으며 이번 작업의 배포 검증으로
주장하지 않는다. 이번 배치에서는 스키마·외부 프로젝트·앱 배포·상시 스케줄러·로컬 앱 데이터를
변경하지 않았고 커밋·푸시를 수행하지 않았다. 격리 DB 테스트는 별도의 테스트 DB를 사용했다.
