# Feature Specification: 002 데이터 모델·관리자·근거 등록

**Feature Branch**: main (existing local checkout)
**Created**: 2026-10-29
**Status**: Complete — local implementation and verification; hosted launch checks remain in 006
**Input**: 002·003·004를 연속으로 진행하여 가져오기→검토·공개→검색·상세 흐름을 완성한다.

## User Scenarios & Testing

### User Story 1 - 허용된 관리자만 편집한다 (Priority: P1)
관리자는 로그인하여 운영 화면에 접근하고 로그아웃할 수 있다.
**Why this priority**: 인증 성공과 편집 권한을 구별하여 비공개 정보를 지킨다.
**Independent Test**: 방문자·일반 계정·허용된 관리자·권한 회수 계정으로 같은 조회와 변경을 시도한다.
**Acceptance Scenarios**:
1. **Given** 방문자 또는 일반 계정, **When** 관리 화면이나 변경 요청에 직접 접근, **Then** 비공개 정보와 수정 권한을 얻지 못한다.
2. **Given** 로그인한 관리자, **When** 로그아웃하거나 관리자 권한이 회수됨, **Then** 후속 변경이 거부된다.

### User Story 2 - 앱과 근거를 초안으로 관리한다 (Priority: P1)
관리자는 앱 기본 정보, 한국 스토어 정보, 별칭, 두 언어의 설명과 공식 근거를 저장한다.
**Why this priority**: 조사 전 정보를 공개하지 않고 축적한다.
**Independent Test**: 초안 저장·재조회·수정 후 공개 목록과 상세에 노출되지 않음을 확인한다.
**Acceptance Scenarios**:
1. **Given** 미등록 앱, **When** 관리자가 저장, **Then** 초안이 생성되고 동일 스토어 ID의 중복 등록은 차단된다.
2. **Given** 번역된 요약, **When** 원문을 수정, **Then** 기존 번역은 검토 필요로 바뀐다.
3. **Given** 같은 공식 문서가 여러 앱을 설명, **When** 각 앱에 근거를 연결, **Then** 출처를 공유하면서 앱별 판정을 유지한다.

### User Story 3 - 근거를 확인하고 공개·정정한다 (Priority: P1)
관리자는 지원 상태와 근거를 검토하고 공개하거나 보관하며 정정 이력을 남긴다.
**Why this priority**: 사용자에게 검증된 판정만 전달한다.
**Independent Test**: 공개 성공, 근거 누락, 동시 편집, 처리 중 실패를 각각 재현한다.
**Acceptance Scenarios**:
1. **Given** 공식 지원·예정·미지원 초안, **When** 공식 근거 없이 공개, **Then** 거부된다.
2. **Given** 확인 필요 초안, **When** 조사 사유와 검토를 확인하여 공개, **Then** 실제 검토 시각과 공개 이력이 함께 저장된다.
3. **Given** 공개 처리 중 저장 실패, **When** 결과 확인, **Then** 판정·근거·이력이 부분 반영되지 않는다.
4. **Given** 공개 앱, **When** 판정을 정정, **Then** 이전 이력이 보존되고 변경 사유와 새 이력이 추가된다.

### Edge Cases
빈 필수값, 비정상 URL, 중복 ID·slug, 충돌하는 수정, 세션 만료, 권한 회수, 저장 실패,
원문 누락·변경, 버전 미공개, 보관 앱 재공개, 잘못된 날짜, 출처 지역·버전 충돌을 다룬다.

## Requirements

### Functional Requirements

- **FR-001**: 관리자 인증과 허용 목록의 권한 확인을 구별하고 모든 변경 요청에서 다시 검사한다.
- **FR-002**: 앱 ID·slug·이름·개발사·카테고리·별칭·발행 상태, 한국 스토어 버전, 원문 언어와 번역을 보존한다.
- **FR-003**: 발행 상태 draft/published/archived와 지원 상태 supported/planned/unknown/unsupported를 별도로 관리한다.
- **FR-004**: 공식 지원·예정·미지원은 출처 URL·제목·원문 발췌와 관리자의 공식 출처 확인을 요구한다. 확인 필요는 조사 사유를 요구한다.
- **FR-005**: 검토 시각은 명시적 검토/공개에서만 기록한다. 수집 시각·스토어 현재 버전·지원 확인 버전과 구분한다.
- **FR-006**: 공개 및 정정은 지원 현황·근거 연결·변경 사유·이력을 전부 저장하거나 전부 취소한다. 과거 이력을 덮어쓰거나 삭제하지 않는다.
- **FR-007**: 초안·내부 메모·관리자 식별 정보는 공개 조회에 포함하지 않는다. 일반 계정은 관리자 목록을 수정할 수 없다.
- **FR-008**: 관리 UI는 한국어/영어·모바일·두 테마·키보드 접근을 지원하고 오류 문구도 번역한다.
- **FR-009**: 원문 변경은 다른 언어 번역을 검토 필요로 표시한다. 동일 앱 동시 편집은 충돌을 알리고 덮어쓰지 않는다.
- **FR-010**: 운영 환경에서 개발용 인증이나 가상 근거가 활성화되지 않도록 차단한다.

### Key Entities

앱, 번역, 스토어 정보, 지원 판정, 출처, 근거, 앱–근거 연결, 변경 이력, 관리자 허용 목록.

## Success Criteria

### Measurable Outcomes

- **SC-001**: 방문자·비관리자의 비공개 조회와 변경 성공 건수 0건.
- **SC-002**: 지원 상태별 공개 요건을 모두 검사하며 누락된 근거/조사 사유를 가진 공개 앱 0개.
- **SC-003**: 실패 주입 시 부분 공개 0건, 정정 이후 이전 이력 보존율 100%.
- **SC-004**: 두 언어·두 테마·360/768/1440px에서 등록→검토→공개 흐름과 키보드 조작을 완료한다.

## Assumptions

- 제품 기준은 docs/PRD.md. 001 완료 상태와 기존 PostgreSQL 로컬 환경을 사용한다.
- 외부 프로젝트 생성·운영 배포는 하지 않는다. 외부 계정 연결의 실환경 검증은 별도로 명시한다.
- 자동 수집/제보 대기열은 005, 출시 환경과 실제 검토 앱 약 100개 목표 최종 충족은 006까지 이어진다. 이번 범위는 가져오기 도구와 약 10개 실제 응답 검증 및 검토 흐름이다.
- 인증 서비스 미설정 시 권한을 자동 부여하지 않는다. 로컬 검증용 신원은 운영에서 금지하며 실제 로그인 검증과 구별한다.
- 테스트용 가상 자료는 전용 검증 DB에서만 사용하며 실제 앱 근거·검토 날짜를 만들지 않는다.
