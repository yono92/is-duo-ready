# 구현 계획

1. `scripts/lib/content-quality.ts`의 버전 관리 SQL 규칙과 `scripts/check-data.ts` 읽기 전용
   CLI를 작성한다. 호스팅 대상·프로젝트 일치와 비공개 설정을 재사용한다. REPEATABLE READ
   READ ONLY에서 읽고 실행 결과·규칙 코드 해시를 `.data/quality/`에 0600으로 남긴다.
2. 공개 스냅샷과 편집 초안을 구별한다. 공개 근거는 스냅샷에 남은 evidence ID와 보존된
   공식 자료로 확인한다. 초안 연결 변경을 공개 근거 소실로 오인하지 않는다. 보류·fallback은 경고다.
3. `DirectoryResult.stats`와 합계 검증을 추가한다. 실제 SQL은 공개 KR 집합→검색 집합→
   페이지→정렬/아이콘→집계를 한 문장에서 계산한다. 개인정보·초안 테이블을 공개 집계에 쓰지 않는다.
4. 홈에 스토어·총수, 상태별 비율 막대와 의미 있는 dl/dt/dd 범례를 추가한다.
   최신 사용자 선택에 따라 Recharts를 별도 클라이언트 번들로 로드한다. 정확한 버전을
   고정하고 Vega 의존성을 제거하며 Astryx core는 유지한다. SVG 가로 정규화 누적 막대와
   Astryx 데이터 색상·툴팁 표면을 사용한다. 집계·범례는 서버에서 제공한다.
   국제화 숫자·라벨·모집단 설명으로 검색 결과 수와 전역 수를 구별한다.
5. 단위·격리 DB·브라우저 검증과 실제 운영 읽기 전용 대조를 수행한다. DB 정정·마이그레이션·
   신규 프로젝트·배포·스케줄러는 필요하지 않다. 앱 수와 근거 판정은 보존한다.

원칙 점검: 공식 근거 판정을 변경하지 않고 published-only/RLS·locale/country·fixture 경계를
유지한다. 숫자 불일치와 조회 실패를 숨기지 않고 반복 가능한 검사와 실제 실행 결과를 남긴다.

6. 전체 공식 자료 재조회: 기존 운영 DB의 1,000개 ID와 근거를 읽기 전용 스냅샷으로 고정한다.
   `rescan-app-evidence.ts`는 기존 제한·검증·재시도 경로로 최대 20개씩 KR Lookup을 읽는다.
   `rescan-app-pages.ts`는 동시 2개·배치 간 750ms 간격으로 공개 제품 페이지를 읽고 해당 앱의
   설명·제품 메타데이터·포함된 버전 기록만 추출한다. 미완료/실패만 재개하며 키워드는 판정이 아니다.
   새 공식 근거와 기존 근거의 재관측 여부, 보류 사유 및 검토 범위를 앱별 자료로 남긴다.
