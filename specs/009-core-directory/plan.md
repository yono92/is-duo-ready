# 구현 계획

## 현재 계획: 통합 앱 탐색 — 2026-11-13

1. PRD·본 명세·설계·작업 목록에 사용자가 승인한 통합 목록 계약을 기록한다.
2. `DirectoryQuery`에서 목록 선택을 제거하고 이전 `collection` URL은 파싱 단계에서 상태로
   정규화한다. 이후 생성 URL은 검색·분류·상태·정렬·페이지만 포함한다.
3. SQL/fixture 모두 전체 공개 앱에서 필터링하고 전체 통계를 계산한다. `familiar` 기본 정렬에
   기존 편집 선정 및 최신 KR 전체 무료 상위 100위 판정을 재사용한다. 차트 테이블이 없는
   환경의 대체 동작과 기존 RLS·공개 경계를 유지하며 마이그레이션은 추가하지 않는다.
4. 기존 Astryx 검색·정렬·버튼을 활용해 검색과 항상 보이는 상태 필터를 먼저 배치한다.
   카테고리 사이드바·모바일 Dialog를 유지하고 전체 통계는 기본 접힘 Collapsible로 옮긴다.
   문구는 ko/en messages에서 관리하며 `unknown` 표시만 판정 의미에 맞게 정리한다.
5. 단위·격리 DB 검사로 URL/정렬/통계 계약을 검증하고, E2E로 검색·필터·언어·뒤로 가기·상세
   복귀·모바일·키보드 동작을 확인한다. lint/typecheck/unit/E2E/build 및 시각 검증 결과를
   `docs/verification.md`에 실제 실행대로 기록한 뒤 작업을 완료 처리한다.

구현 전 원칙 검토: 공식 근거·검토일·실데이터를 변경하지 않으며 언어/KR 독립, fixture 차단,
공개 권한·키보드·테마·URL 경계를 유지한다. 운영 변경과 배포는 범위에 포함하지 않는다.

## 이전 계획 — 2026-11-03

기존 서버 SQL/fixture 검색 경로에 `collection` 조건을 추가한다. 주요 앱의 App Store ID를
버전 관리하는 편집 목록에 두고, 기존 공개 차트 테이블의 KR 전체 무료 관측과 합친다.
목록 포함 여부는 지원 판정과 독립적이며 공개 앱만 대상으로 한다. 차트 테이블이 없는
환경은 편집 목록으로 작동한다. 기존 RLS를 통해 읽으며 private 테이블을 공개하지 않는다.

기존 Astryx 버튼과 검색·필터 레이아웃을 사용한다. 목록 선택과 설명은 통계 앞에 두고,
통계는 선택 목록에 한정한다. 사용자 문구는 ko/en messages에 둔다.

필수 lint/typecheck/unit/E2E/build와 격리 DB 통합 검증을 실행하고 실제 결과를 기록한다.
