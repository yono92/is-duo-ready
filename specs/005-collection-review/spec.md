# Feature Specification: 005 변경 수집·검토·제보

**Feature Branch**: main (existing local checkout)
**Created**: 2026-10-29
**Status**: Complete — local implementation and verification; hosted scheduling/deployment remains 006

## User Scenarios & Testing

### User Story 1 — 등록 출처 변경 확인 (Priority: P1)
관리자는 앱의 KR 스토어 또는 승인된 공식 웹 출처를 감시 대상으로 등록하고 작은 배치로 확인한다.
**Why this priority**: 공개 정보를 유지하면서 새 근거를 놓치지 않기 위해서다.
**Independent Test**: 테스트 전용 출처의 내용 변경·동일 응답·장기 실패를 실행하고 후보와 실패 기록을 확인한다.
**Acceptance Scenarios**:
1. Given 등록 출처, When 내용 또는 버전 변경, Then 이전/현재 관측과 후보를 비공개로 보존하고 공개 상태·검토일은 그대로다.
2. Given 동일 콘텐츠 또는 기각된 콘텐츠, When 재수집, Then 같은 후보를 재생성하지 않는다.
3. Given 오류/삭제/시간 초과, When 수집, Then 기존 상태를 보존하고 실패·재시도·연속 실패를 표시한다.
4. Given 동시 실행 또는 중단, When 다음 배치 실행, Then 실행 잠금으로 중복 처리를 막고 만료 실행을 복구한다.

### User Story 2 — 후보 검토와 공개 반영 (Priority: P1)
관리자는 공개 정보와 변경 후보·출처를 비교하고 기존 편집기로 판정과 근거를 준비한 뒤 승인·보류·기각한다.
**Why this priority**: 수집과 공개 승인 권한을 분리한다.
**Independent Test**: 보류/재개/기각/승인 및 오래된 화면의 승인을 검증한다.
**Acceptance Scenarios**:
1. Given 대기 또는 보류 후보, When 명시적으로 승인, Then 검증된 지원 판정·근거 연결·공개 이력·처리 상태가 함께 저장된다.
2. Given 근거 미완성 또는 동시 수정, When 승인, Then 부분 공개나 완료 처리 없이 실패한다.
3. Given 후보, When 사유를 넣어 보류/기각, Then 공개 정보는 유지되고 처리자·사유는 비공개로 남는다.

### User Story 3 — 비회원 제보와 관리자 처리 (Priority: P2)
방문자는 앱 추가 또는 정보 정정을 로그인 없이 제보한다. 관리자는 제보를 확인하고 대상 앱에 연결하여 같은 검토 흐름으로 처리한다.
**Why this priority**: 자동 수집으로 찾지 못하는 신규 앱과 정정을 보완한다.
**Independent Test**: 비회원 접수→관리자 목록→앱 연결→검토, 과도 요청 차단, 비공개 접근 거부를 확인한다.
**Acceptance Scenarios**:
1. Given 공개 상세 또는 제보 페이지, When 유효한 앱 URL·제보 종류·내용·근거 URL 제출, Then 비공개 접수 확인만 표시한다.
2. Given 부적절 입력/과도 요청, When 제출, Then 저장을 제한하고 번역된 오류를 표시한다.
3. Given 제보, When 관리자가 검토 전, Then 공식 근거가 되거나 자동 공개되지 않는다.

### Edge Cases
수집 중 삭제/리디렉션/사설 IP DNS/과대 응답/robots 거부, 동일 버전의 다른 릴리스 노트,
출처 일시 중단·재개, 두 관리자 동시 승인, 신규 제보의 아직 없는 앱, 중복 제출,
권한 회수·비회원의 액션 재호출, 원문 누락·긴 URL·HTML 입력, 양 언어·테마·좁은 화면.

## Requirements
### Functional Requirements
- **FR-001**: 일 단위 기본 주기의 등록 출처를 작은 배치로 확인하고 수동 재확인을 지원한다.
- **FR-002**: 스토어 API와 일반 웹 출처를 분리하고 승인된 공식 호스트만 수집한다. 내부 주소와 우회 리디렉션은 거부한다.
- **FR-003**: 요청 시간·응답 크기·재시도 횟수를 제한하고 지수 백오프·실행 잠금·실패 기록을 제공한다.
- **FR-004**: 콘텐츠 동일성을 기준으로 후보를 중복 제거한다. 기각한 동일 근거는 재등록하지 않는다.
- **FR-005**: 새 버전과 릴리스 노트, 이전 관측을 보존하며 수집만으로 공개 판정·검토일·이력을 바꾸지 않는다.
- **FR-006**: 검토 화면은 공개 정보/후보/출처·근거 문구를 비교하고 승인·보류·기각 사유를 요구한다.
- **FR-007**: 승인은 기존 공식 근거 검증을 통과해야 하며 공개 정보·근거·이력·검토 처리를 함께 반영한다. 충돌 시 다시 확인한다.
- **FR-008**: 제보는 연락처를 요구하지 않고 종류·대상 KR 앱 URL·내용·근거 URL을 검증한다. 목록·내부 사유는 비공개다.
- **FR-009**: 제보 속도를 서버에서 제한하고 중복을 억제하며 제보 내용을 자동 공식 근거로 승격하지 않는다.
- **FR-010**: 관리자 권한은 각 변경 요청에서 확인한다. 일반 로그인/비회원은 운영 데이터에 접근할 수 없다.
- **FR-011**: ko/en·라이트/다크·360/768/1440px·키보드 접근을 검증하며 외부 실패와 실제 빈 상태를 구분한다.
- **FR-012**: 로컬 반복 실행과 단발 배치를 제공한다. Preview에서 운영 정기 실행을 금지하고 운영 스케줄러는 하나만 사용한다.

### Key Entities
- 감시 출처: 앱·출처 종류·공식 URL·감시 허용·확인 주기·마지막 성공·연속 실패.
- 수집 실행/관측: 실행 시각·시도 수·오류·이전/현재 콘텐츠·동일성 표식.
- 검토 항목: 앱·수집/제보 후보·상태·사유·처리자·충돌 방지 버전.
- 제보: 추가/정정·앱 URL·내용·근거 URL·접수 시각; 검토 항목에 연결.

## Success Criteria
### Measurable Outcomes
- **SC-001**: 동일 변경을 세 번 확인해도 후보는 하나이며 승인 전 공개 데이터는 동일하다.
- **SC-002**: 승인 실패 주입 시 공개 정보와 검토 상태 모두 이전 상태를 유지한다.
- **SC-003**: 비회원과 일반 로그인은 모든 운영 목록을 읽거나 승인할 수 없다.
- **SC-004**: 두 언어·두 테마에서 제보/검토/수집 핵심 흐름을 키보드로 완료하고 세 화면 폭에서 가로 넘침이 없다.
- **SC-005**: 전체 회귀·DB·브라우저·빌드 검증 결과와 운영 연결의 남은 사항을 기록한다.

## Assumptions
- 002–004의 인증·편집·공개 승인·KR 스토어 어댑터를 재사용한다.
- 수집 허용 조건을 관리자가 확인한 공식 웹 문서만 등록한다. robots 확인 불가/거부는 보수적으로 수집을 중단한다.
- 신규 앱·공식 발표의 주간 조사는 관리자 수동 운영과 제보로 보완한다. 임의 웹 검색 자동화는 포함하지 않는다.
- 005는 로컬 구현과 검증이다. 실제 Supabase/Vercel 연결·운영 Cron 활성화·100개 실제 콘텐츠 확보는 006이다.
- 제보 남용 방지는 서버 제한과 전체 접수 상한으로 시작한다. 공개 서비스의 신뢰 가능한 프록시/IP 정책은 배포 시 검증한다.

## 관리자 서버 상태 관리 — 2026-10-29

사용자 승인에 따라 TanStack Query를 출처 수집 현황에 먼저 적용한다. 공개 목록·URL 필터·폼 로컬 상태는 기존 책임을 유지하며 Zustand는 실제 화면 간 공유 상태 기능과 함께 도입한다.

- 서버에서 읽은 초기 현황을 표시하고, 활성 화면에서 15초마다 읽기 전용 현황을 다시 조회한다. 백그라운드 탭에서 주기 조회하지 않으며 조회 자체가 수집을 실행하지 않는다.
- 등록·감시 일시정지/재개·수집 액션 완료 후 Query 캐시를 무효화하여 결과를 바로 반영한다. 기존 Server Action의 권한 검사와 공개 갱신 계약을 유지한다.
- 각 현황 요청은 관리자 권한을 검증하고 HTTP 공유 캐시·브라우저 영구 저장을 사용하지 않는다. 캐시는 화면 인스턴스에 한정하며 서버 요청이나 관리자 간 공유하지 않는다.
- 조회 장애 시 마지막 결과와 번역된 갱신 실패 안내·수동 재시도를 표시한다. 401/403을 받으면 비공개 목록과 조작 UI를 숨기고 주기 조회를 중단한다.
- 브라우저에서 자동 갱신, 액션 후 갱신, 장애 복구, 권한 회수를 검증한다.
