# Feature Specification: 003 공개 DB 연동·앱 상세·이력

**Feature Branch**: main (existing local checkout)
**Created**: 2026-10-29
**Status**: Complete — local implementation and verification; hosted launch checks remain in 006
**Input**: 002·003·004를 연속으로 진행하여 가져오기→검토·공개→검색·상세 흐름을 완성한다.

## 상세 날짜·등록 이력 후속 결정 — 2026-10-30

- 근거 카드에는 발표일·출시일이나 날짜 미확인 문구를 표시하지 않는다. 저장된 날짜는 보존하며 날짜 채우기를 이번 범위에 포함하지 않는다.
- 상세 변경 이력은 최초 등록을 조회·페이지 수 계산에서 제외한다. 이후 지원 상태 변경 또는 같은 상태에서의 근거 정정이 없으면 섹션을 표시하지 않는다.
- 전체 업데이트 목록에는 서비스 등록 기록을 유지하되 등록 작업 설명을 숨기고 ko/en 메시지로 서비스 등록임을 구분한다.
- 상태가 바뀌지 않은 정정도 보존하고 “지원 정보 정정”으로 표시한다. 기존 원문 fallback·정보 반영일·접근성·테마·KR 경계는 유지한다.

## User Scenarios & Testing

### 메인 무료·유료 인기순 — 2026-11-02

기본 정렬은 KR 전체 무료 인기순이다. 정렬 메뉴에 무료/유료 인기순과 기존 정렬 3가지를
제공하며 탭으로 디렉터리를 분할하지 않는다. 공개 앱에 대응하는 공식 차트 관측을 별도
RLS 테이블에 저장한다. 무료·유료 모두 공식 지원 앱 전체를 먼저 표시하고 각 그룹에서
순위순으로 정렬한다. 순위 없는 지원 앱도 지원 미확인 1위보다 앞선다. 순위 없는 앱은
각 그룹 뒤에 유지하고, 자료가 없으면 공식 지원 우선·그룹 내 이름순 대체를 안내한다. 전체 차트·수집일·원문 링크와 카드 순위를 제공한다. 카테고리별 차트
순위는 혼합하지 않으며 자료 갱신은 별도 CLI로 원자적으로 실행하고 지원/검토/이력은 보존한다.

### 발표일 저장 기능 제거 — 2026-11-02 후속 결정

발표일을 관리자 입력·가져오기 제안·공개 DTO·DB 컬럼에서 제거한다. 새 007 마이그레이션은
save/publish/import 함수·근거 fingerprint를 갱신하며 현재 스냅샷과 후보의 날짜 키를 제거한다.
근거 ID·외래키·RLS·검토 시각·불변 변경 이력은 보존하고, 날짜만 다른 중복이 있으면 원자적으로
실패한다. 날짜가 없는 기존 자료와 날짜가 있던 자료 모두 저장·공개·재입력 중복 방지가 동작해야 한다.

### User Story 1 - 실제 공개 앱을 검색한다 (Priority: P1)
방문자는 기존 검색·필터·정렬·페이지 이동으로 검토된 앱을 찾는다.
**Why this priority**: 001 탐색 화면에 실제 공개 정보를 제공한다.
**Independent Test**: 공개·초안·보관 앱을 준비하고 두 언어의 이름·별칭 검색과 복합 필터를 확인한다.
**Acceptance Scenarios**:
1. **Given** 공개 앱과 초안이 함께 있음, **When** 검색·페이지 이동, **Then** 공개 앱만 표시된다.
2. **Given** 조회 실패, **When** 목록 방문, **Then** 빈 결과와 구분되는 오류·재시도 안내를 표시한다.
3. **Given** DB 모드, **When** 데이터가 없거나 조회 실패, **Then** 가상 앱으로 대체하지 않는다.

### User Story 2 - 근거와 버전·이력을 확인한다 (Priority: P1)
방문자는 상세에서 한국 스토어 기준, 현재 버전, 지원 확인 버전, 검토일, 공식 근거와 공개 이력을 확인한다.
**Why this priority**: 앱 지원 판단의 근거를 이해한다.
**Independent Test**: 근거가 있는 앱과 확인 필요 앱의 상세 및 언어 전환을 확인한다.
**Acceptance Scenarios**:
1. **Given** 영어 상세, **When** 버전·근거 확인, **Then** 한국 스토어 정보와 동일한 판정을 표시한다.
2. **Given** 누락되거나 검토 필요한 번역, **When** 상세 방문, **Then** 원문과 원문 표시 안내를 제공한다.
3. **Given** 과거 slug, **When** 접근, **Then** 현재 공개 앱의 주소로 이동한다. 초안/보관 앱은 공개되지 않는다.

### User Story 3 - 최신 공개 변경을 본다 (Priority: P2)
방문자는 최근 업데이트 목록에서 실제 지원 정보 변경을 확인한다.
**Why this priority**: 단순 스토어 업데이트와 검토 결과 변경을 구별한다.
**Independent Test**: 공개·정정 후 목록·상세·업데이트가 새 상태를 표시하는지 확인한다.
**Acceptance Scenarios**:
1. **Given** 관리자 공개 성공, **When** 다음 탐색, **Then** 두 언어의 목록·상세·업데이트에 새 정보가 반영된다.
2. **Given** 스토어 현재 버전만 갱신, **When** 업데이트 목록 확인, **Then** 지원 변경일이나 검토일이 바뀌지 않는다.

### Edge Cases
DB 미설정·연결 실패·빈 결과·없는 slug를 구분한다. 숨김 앱의 과거 주소, 잘못된 페이지,
번역 검토 필요, null 버전·발표일, 긴 원문, 외부 링크와 악성 HTML 입력을 다룬다.

## Requirements

### Functional Requirements

- **FR-001**: 공개 목록·상세·업데이트는 published 앱과 공개 가능한 필드만 조회한다.
- **FR-002**: 001의 검색·필터·정렬·24개 페이지·URL 보존·언어/테마 동작을 유지한다.
- **FR-003**: 가상 데이터와 실제 데이터의 모드를 명시적으로 구별하고 운영 fixture 차단을 유지한다.
- **FR-004**: 상세는 출처 제목·날짜·원문 발췌·링크, 확인된 기능, 현재 및 지원 버전, 검토일, 공개 이력과 수정 제보 동선을 제공한다.
- **FR-005**: 공개 이력은 관리자 개인정보와 내부 메모를 제외하고 변경 사유·공개 전후 판정을 표시한다.
- **FR-006**: 공개·정정·보관 직후 두 언어의 목록·상세·업데이트 캐시를 갱신한다.
- **FR-007**: 과거 slug는 현재 공개 slug로 연결하며 초안·보관 앱은 이전 주소로도 조회할 수 없다.
- **FR-008**: 언어별 canonical/hreflang을 제공하고 공개 sitemap에는 공개 앱만 포함한다. 개발·Preview는 색인을 차단한다.
- **FR-009**: 번역 fallback·KR 기준·접근성을 유지하며 외부 콘텐츠를 실행 가능한 HTML로 렌더링하지 않는다.

### Key Entities

002의 공개 앱·지원·근거·번역·이력, 과거 slug 연결.

## Success Criteria

### Measurable Outcomes

- **SC-001**: 공개 조회·상세·업데이트·사이트맵에서 초안과 내부 정보 노출 0건.
- **SC-002**: 공개 성공 후 다음 조회에서 두 언어의 새 상태 확인, 보관 후 공개 노출 0건.
- **SC-003**: 001 탐색 회귀 검증을 모두 통과하고 오류를 빈 결과로 잘못 표시하는 사례 0건.

## Assumptions

- 제품 기준은 docs/PRD.md. 001 완료 상태와 기존 PostgreSQL 로컬 환경을 사용한다.
- 외부 프로젝트 생성·운영 배포는 하지 않는다. 외부 계정 연결의 실환경 검증은 별도로 명시한다.
- 자동 수집/제보 대기열은 005, 출시 환경과 실제 검토 앱 약 100개 목표 최종 충족은 006까지 이어진다. 이번 범위는 가져오기 도구와 약 10개 실제 응답 검증 및 검토 흐름이다.
- 인증 서비스 미설정 시 권한을 자동 부여하지 않는다. 로컬 검증용 신원은 운영에서 금지하며 실제 로그인 검증과 구별한다.
- 테스트용 가상 자료는 전용 검증 DB에서만 사용하며 실제 앱 근거·검토 날짜를 만들지 않는다.
