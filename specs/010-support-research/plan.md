# 구현 계획

조사 결과는 검토 가능한 버전 관리 JSON에 실제 출처·한영 요약을 기록하고 공개 상세에서
등록된 한국 App Store ID로 매칭한다. 기록이 없는 앱에 시각이나 조사 결과를 생성하지 않는다.
기존 수집·검토 모델을 재사용하며 개발사 URL 후보와 실제 모니터 등록/활성화는 구분한다.

기존 submission ingress에 usage 유형을 추가한다. 구조화된 환경·공개 동의를 SQL과 서버에서
검증한다. PNG/JPEG/WebP 최대 2MiB 1장을 서버에서 디코딩·방향 보정·축소하고 메타데이터 없는
1MiB 이하 WebP로 저장한다. 비공개 첨부와 승인 공개 스냅샷은 별도 RLS 테이블로 관리한다.
관리자 승인 분기는 공식 앱 publish를 호출하지 않으며 승인된 관찰만 공개한다.

상세·제보·관리자 검토는 기존 Astryx 컴포넌트와 messages를 사용한다. 공개 이미지도 no-store로
전달해 철회·앱 보관 경계를 유지한다. DB 배포 전에는 조회 오류를 빈 제보와 혼동하지 않는다.
새 외부 프로젝트나 정기 작업은 만들지 않는다. 기존 프로젝트 배포는 검증 완료 후 기존 흐름을 따른다.
